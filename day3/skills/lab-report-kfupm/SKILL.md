# KFUPM Lab Report

Use this skill when the user requests a lab report, experiment summary, or practical-session write-up.

Follow this structure exactly:

1. **Title** — specific experiment or system name.
2. **Objective** — one measurable sentence.
3. **Method** — 3–5 numbered steps describing what was actually performed.
4. **Results** — observed outputs, measurements, or verified behavior; never invent missing values.
5. **Discussion** — connect each important result to the objective and identify one limitation.
6. **Conclusion** — 2–3 sentences stating whether the objective was achieved.
7. **Evidence** — commands, logs, files, or sources used to verify the result.

Rules:

- Keep the report below 500 words unless the user requests otherwise.
- Clearly label unknown or unmeasured values as `Not measured`.
- Do not claim that a command, test, container, API, or agent worked without evidence.
- Use precise technical language; avoid marketing phrases and filler.
- Never include API keys, `.env` contents, access tokens, or other secrets.
